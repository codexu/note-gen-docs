This page covers NoteGen client operations. An administrator must first complete [Self-hosting](/en/docs/self-hosted) and verify HTTPS, readiness, database backup, and object-storage backup. Self-hosted sync is currently experimental.

## Prepare

1. Export a local ZIP and back up the Markdown workspace on the existing device.
2. Ask the administrator for the server URL, account method, and compatible client version.
3. Enable Developer Mode so self-hosting appears under Sync.
4. Do not let another sync engine write to the workspace that will be bound.

## Sign in

Open Settings → Sync → NoteGen Self-hosted, accept the experimental warning, and enter the server URL. Prefer browser authorization. When allowed by the instance, login, password, and optional TOTP are also available.

NoteGen does not silently downgrade an HTTPS address to HTTP. An HTTP URL shows an insecure warning and should only be used for controlled local testing, never over the public internet.

## Bind a library

After connection, NoteGen prepares a default library for the current workspace. You can also:

- create a library with its own local directory;
- switch the current workspace to an existing library;
- see whether access is read-only or read-write;
- switch local workspaces by selecting another library.

Verify the current path and library name before binding. Selecting a remote library can switch the local workspace; it does not merely rename the original directory.

## Members and invitations

Authorized members can invite an account by login and assign Viewer, Editor, or Manager, then refine capabilities such as history view/restore, invitations, member management, rename, and delete. Invitations can be accepted from the recipient's list or shared as a link.

Grant the minimum access required. Removing a member does not erase copies that person already exported.

## Personal data and conflicts

Workspace files and personal data such as records, tags, chats, canvases, and settings can have separate synchronization scopes. On first connection, decide whether local or remote state is authoritative.

If a local workspace is incorrectly bound to multiple libraries, the client shows a conflict. Transfer it to the correct library or keep a local copy. Disable automatic sync and export a ZIP before resolving; do not repeatedly overwrite both sides.

## Disconnect and recover

Disconnecting does not automatically delete the local workspace. Preserve the server URL, account and recovery information, and local backup before reconnecting. If login fails, check readiness, certificate, device time, and the browser callback, then contact the instance administrator. Never post passwords, TOTP codes, recovery keys, or invitation links in a public issue.

## Personal data switches and attachments

Pause tags, records, conversations, messages, memories, and settings separately. Pausing tags also pauses dependent records, linked notes, canvases, and messages; pausing conversations also pauses messages. Re-enabling retrieves the remote snapshot, preserving pending local changes before replacing the same item. Pausing a domain does not remove downloaded data.

Attachment transfer covers local resources managed by NoteGen. Files at external locations still need separate backups. Pausing personal attachment transfer does not remove downloaded files. Workspace attachments sync with their notes.

Login tokens and sync keys use the system credential store: macOS Keychain, Windows Credential Manager, Linux Secret Service, and the existing mobile Keychain / Keystore storage. Linux requires an available, unlocked desktop keyring. An unavailable credential store causes an explicit connection error. Legacy plaintext credentials are removed only after migration and individual readback verification succeed.

## Recover after a failed switch

Newer clients save and verify files, personal database rows, and sync mappings before switching. If switching fails, choose **Restore data from before the switch** in the review window:

1. The client saves a fresh safety copy before every recovery attempt or retry, retaining earlier copies.
2. Notes and attachments are copied into a separate recovered workspace; the original workspace is retained.
3. Personal data returns to the snapshot, and the client switches to local storage. Server data is retained.
4. Check files and records before choosing a sync provider again. The window shows the recovered workspace and safety-copy locations.

The progress window stays open during recovery. If local records change after the safety copy is saved, the client stops database replacement; review the changes before retrying. Sensitive settings remain unchanged when either the backup or the current client excludes them. If recovery is interrupted, restart the client and continue recovery before enabling sync. Older snapshots containing only files and personal-data.json remain available for manual recovery through the backup-folder action. They cannot be automatically restored by the newer recovery flow.
