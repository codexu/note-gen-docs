同步可能覆盖文件或结构化数据。开始前先在已有完整数据的设备上导出本地 ZIP，并确认备份已保存到 NoteGen 工作区之外。

## 选择方式

- **GitHub、Gitee、GitLab、Gitea**：适合 Markdown 文件版本管理。
- **S3、WebDAV**：适合对象存储或自有 NAS。
- **OneDrive、iCloud Drive 或其他云盘文件夹**：由系统云盘同步工作区文件。
- **NoteGen 自托管**：实验性方案，可同步文件和应用数据并管理远程资料库。

不要让两种同步工具同时管理同一个工作区，例如同时启用 Git 同步和第三方网盘同步，除非你清楚冲突处理方式。

## 第一台设备

1. 配置并测试同步平台。
2. 确认当前工作区和远程仓库/路径对应正确。
3. 手动上传 Markdown 与资源。
4. 开启记录与配置同步时选择“上传本机数据”。
5. 等待同步状态完成后再操作第二台设备。

## 第二台设备

1. 安装相近版本的 NoteGen，并先导出空白或现有数据备份。
2. 配置同一平台、仓库和路径。
3. 先执行远程拉取，不要立即上传本机内容。
4. 首次启用记录与配置同步时选择“拉取远程数据”。
5. 检查笔记、资源、记录、标签和设置后，再开启自动同步。

## 冲突与恢复

“合并两边内容”适合双方都有新增记录的情况；“远程覆盖本机”和“本机覆盖远程”都会丢弃一侧未同步修改。处理前先备份，并确认哪台设备保存了最新数据。

如果结果不正确，立即关闭自动同步，保留远程仓库/存储不变，从 ZIP 恢复到一台设备，确认内容后再重新建立同步关系。更多字段和平台权限参见[同步配置](/cn/docs/settings/sync)。
