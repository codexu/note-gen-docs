## 目标与范围

将现有 React 复刻组件更新到可追溯的 NoteGen 界面基线，供首页演示、组件画廊和中英文 MDX 共用。保留可组合组件，补齐新增功能的可见状态与必要的演示交互。

“完美复刻”的验收对象是指定平台、主题、语言、窗口尺寸与状态下的界面。源码确认结构与条件；应用实图确认实际尺寸、字体、间距和浮层位置。方案制定时只做了源码调研，首批实施也未对运行中应用截图，因此下述缺口不等于完整的像素差异清单，也不能宣称已经完成视觉验收。

不移植 Tauri、应用 stores、数据库、文件系统、AI、同步或插件执行引擎。浏览器页面使用本地示例内容，终端使用固定输出，安装与审批只切换演示状态。真实第三方网页、系统权限窗口、系统通知可保留截图或专门说明，避免画成 NoteGen 自有界面。

## 设计决策

### 组件分层与复用

沿用 `components/notegen`，不另建一套复刻库：

1. **基础层**：现有 Frame / Panel / Toolbar / IconButton，补充经对照确认的语义尺寸和主题样式。
2. **功能层**：标题栏、状态栏、记录、标签页、编辑器、Agent、画布、设置、移动端、反馈；浏览器与插件可各增加一个同级文件。
3. **场景层**：桌面完整场景、移动完整场景、设置详情、审批与浏览器等局部预览。
4. **接入层**：首页、画廊、`NoteGenDocPreview` 与 MDX。

完整桌面组件目前位于 `components/home/notegen-desktop-replica.tsx`。先替换内部重复绘制为共享功能组件，再考虑迁移到组件库；若迁移，旧路径保留兼容导出，公共 `@/components/notegen` 导出不变。移动端同样先确认当前首页实现是否仍在使用，再做替换，不能仅凭名称删除旧函数。

### 数据与状态契约

- 视觉组件接收明确的 `lang`、数据和状态 props；保持现有 `cn | en` 语言约定。
- 标签类型增加时用可区分联合：文件、记录、画布、空白、插件、浏览器各有自己的字段，避免所有字段都可选。
- 交互支持局部受控状态与回调，例如当前标签、只读、审批状态和当前题目；完整演示可提供内部状态。只为实际场景增加 props，不提前设计万能配置系统。
- 展示数据使用固定 ID、时间、计数和终端输出。轮播只在首页需要时启用；画廊与文档默认固定状态，方便对照。
- 状态枚举与转换依据源码。审批、安装、同步不能只画“成功”；依场景覆盖待处理、进行中、拒绝/失败和完成。
- 版本信息集中在场景数据中，注明展示基线；同步更新中英文示例，避免多个组件各写一个版本号。

### 尺寸与主题

现有 Frame 有响应式小字号，`doc-preview.tsx` 在 1120 × 650 内绘制后缩放。应用指南记载默认桌面窗为 1360 × 720。两者均需保留为对照样本，先核对后决定是否统一场景基准，不能直接以应用默认窗口取代所有文档尺寸。

建议将自然尺寸与容器缩放分开：组件负责真实几何关系，预览容器负责缩放。先迁移一个完整场景比较阅读性，再逐族替换小字号；禁止局部盲目放大导致面板比例漂移。

颜色沿用本站语义变量，图标对照源码的 Lucide 图标、尺寸、描边。应用和官网 token 差异只在复刻容器内映射，避免为复刻更改全站 UI。浅色/深色分别检查，不用滤镜生成另一种主题。

### 设置页面的特殊处理

通用开关、输入与普通设置行继续使用 `settings-data.ts`。插件市场、权限确认、赞助额度、CSS 编辑器等具有明确结构的界面使用专用组件；不要把所有页面压成统一的几行设置项。分类、排序、文案、开发者模式和平台可见性以应用 `setting/config.tsx` 和页面源码为准。

- 逐一核对场景内可点击控制是否正确改变演示状态；纯视觉项不要伪装为可操作按钮。
- 检查完整场景、画廊、MDX 的同一部件是否一致，以及浮层是否被容器裁剪。
- 记录实图与复刻截图的相同尺寸及状态。有截图才能报告视觉结果；无截图只报告源码对照。

遵循用户约定：没有明确要求，不主动运行测试、Lint、类型检查或构建，也不为了验收自行启动开发服务器。可做静态阅读、调用点核对及用户授权的已有预览检查。最终分别报告已做的核对和未做的验证。
